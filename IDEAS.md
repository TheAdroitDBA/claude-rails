# Ideas

- 2026-05-18 | parallel-dev backlog with file claims: current `.claude/current-feature` LIFO stack conflates real pivots (parent blocked by child) with "work on this next" (no dependency). Proposed: split into (a) single-slug active feature, (b) `features/BACKLOG.md` ordered list of features-to-pick, (c) pause/blocked-by stack only when a feature is genuinely blocked. Each backlog entry declares file claims (reuse existing `## Scope` / `## Files`). Multiple devs can pick concurrently if claims don't overlap -- framework refuses overlapping picks. Surfaces conflicts at backlog-pick time instead of git-merge time. Real example: bug-index and rails-managed-blocks both claimed commands/w.md and commands/project-setup.md -- the system would have caught this. Hard parts to spec when promoted: claim visibility (committed vs. live registry), cross-cutting work (repo-wide renames can't be non-overlapping), claim drift mid-feature, what happens to claims when a feature pauses. Promote to ADR -> feature when parallel-dev pain actually arrives. Also obsoletes/absorbs features-index.
- 2026-05-18 | what-vs-how separation: feature docs mix the "what" (Success Criteria, Surface, Scope, Files, Test Plan -- publishable) with the "how" (Progress checklist, Deviation, Interrupts, commit hashes, NEXT line -- session-only). Auto-documenter via docs.export.yml has to filter by section name, which is brittle. Proposed convention: any section under an `<!-- internal -->` HTML comment is filtered out of export. Single rule, scales. Bugs already follow this shape: BUG-INDEX is the "what" (publishable), KNOWN-ISSUES is the "how" (Repro/Evidence -- investigator-facing). Apply same separation cleanly to features. Tackle after features-index.
- 2026-05-17 | features-index: mirror bug-index pattern for feature docs. /n and /fs maintain features/INDEX.md with one-line entries (slug, status, surface flag, last-touched, path). New /f repurposed as lightweight resume (reads INDEX + top-of-stack only); old /f finalize work absorbed into /fs. /w refactored to read indexes only, never full docs. Naming becomes symmetric: /n open, /f resume, /fs close (mirrors /b, /t, /bs). Solves 16k+ token cold-start when starting next feature. Do AFTER bug-index ships (validates the pattern first). Also: add a CLAUDE.md principle "future-work discussions get captured via /i before context shifts" -- same shape as "Learn from failures" but for ideas not corrections.
